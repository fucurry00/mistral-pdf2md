**プロジェクト目的**

講義PDFを、AIエージェントが検索・引用・部分読解しやすい **原文参照つき `curated.md`** に変換する。

目的は人間向けの美しいMarkdown清書ではなく、`claude code`、`codex`、`cowork` などローカルAIエージェントが扱いやすい知識ソース化。
`claude.ai` / `chatgpt.com` のプロジェクト知識向け軽量エクスポートは将来検討とし、第一版の主対象にはしない。

**権威と成果物**

「正本」という語は過負荷だったため廃し、3概念を分ける。

- **権威 (source of truth)**: PDF元本。忠実性の最終基準であり、人間が照合する対象。
- **第一成果物**: `curated.md`。パイプラインが産み、AIエージェントが消費する出力。
- **永続成果物**: PDF元本 + `curated.md`。バージョン管理・保存する正規セット。

`raw`、`normalized`、OCR候補、LLM編集候補、適用差分などは永続成果物ではなく、変換・検証・デバッグ用の内部証跡として扱う。

保存方針:

- 通常実行: PDF元本 + `curated.md`(frontmatter に metadata を含む)
- `--debug`: raw / normalized / 抽出ブロック / LLM編集候補 / 適用差分を保存
- 検証失敗時: debug bundle を自動保存
- テスト実行時: debug bundle を保存して回帰確認に使う

*(改訂)* 原本「正本と成果物」L8-15 の「正本」を権威/第一成果物/永続成果物に分離(Q7-1)。

**入力スコープ**

第一版は講義資料PDFを対象にする。
Word / HTML / Google Docs / 写真入力は将来の入力アダプタとして見越すが、第一版の成功条件には含めない。

PDFは高品質なテキストレイヤーを持つとは限らないため、text layer 前提にはしない。

**抽出方針**

第一版の抽出 primary は **Mistral OCR 単源**。ブロック分類・ノイズ判定・構造復元はこの単源 Markdown 上で行う。

採否の根拠:

- OCR の弱点(文字誤認、視覚ノイズ取り込み)は**下流のパッチ層で回復可能**(局所OCR誤り修正・反復ヘッダー除去・ページ番号除去は自動適用パッチ)。
- text layer の弱点(読み順崩壊、段組/スライド配置、文字分断、文字化け、**画像内文字を拾えない**)は**回復不能**(壊れた読み順は事後復元できず、存在しない文字は作れない=捏造になる)。
- 「重み付け・衝突検出」といった複雑な判定は 2源を突き合わせる時にしか発生しない。1源に決めれば消える。
- 第一版の主対象は講義スライドPDFで、段組・図中ラベル・画像化テキストが多く、text-layer の欠点が最も致命的に出る。

**多源統合(PDF text layer + OCR + layout 解析をブロック単位で統合し、重み付け・衝突検出する方式)は v2 に降格。** v2 では block 単位の融合ではなく、document/page 単位の単純ルーティング(クリーンな単段組テキストレイヤーがあり画像文字が無いページ → text layer、それ以外 → OCR)から検討する。

*(改訂)* 原本「抽出方針」L31-42 の多源統合を v1 必須から外し v2 へ(Q1)。原本 L40「LLM patch」は抽出候補ではなく編集モデル(後述)へ移動。

**ブロック分類**

第一版のブロック種別は最小限にする。

- `title`
- `heading`
- `paragraph`
- `list_item`
- `table`
- `figure_caption`
- `header_footer`
- `page_number`
- `unknown`

- `title`
- `heading`
- `paragraph`

- `table`

**curated.md の性質**

`curated.md` は要約ではなく、原文に忠実な再構成文書にする。
講義資料に含まれる主張、定義、例、手順、注意点は落とさない。削るのは反復ヘッダー、ページ番号、装飾、明らかな重複などに限定する。

ただし `curated.md` は人間が快適に通読するための文書ではない。
AIが検索・引用・部分読解しやすい中間成果物であり、忠実性の権威は PDF元本。見た目が必要なら、将来 `curated.md` からHTMLなどを派生生成する。

**粒度と分割**

通常PDFは、PDF 1本につき `curated.md` 1本を基本にする。

大型PDFの場合:

- `curated.md` は目次・概要・章リンク中心
- 本文は章単位ファイルへ分割
- 分割判断はページ数だけでなく、抽出後の文字量・見出し構造・章境界で決める

想定サイズ:

- 通常: 講義資料 10〜80ページ程度
- スライドPDFなら100ページ前後でも文字量が少なければ1本で可
- 100〜150ページ超、文字密度が高い、5〜10万トークン級なら分割対象

**原文参照**

**内部不変条件(要件):**
パイプラインは**全ブロックに出自ページ(範囲)タグを付与しなければならない**。タグは OCR 時点で付き、編集でブロックを併合したら union 伝播する(例:ページ跨ぎの段落を再接合 → p.12-13)。**出自ページを付与できないブロックがあれば emit は fail-closed**(黙って欠落させない)。
この block→page タグが**ページ参照の唯一の source of truth**であり、(a) セクションのページ範囲算出、(b) 編集ゲートの「`before` が原文に実在するか」照合、の両方の基盤になる。

> 注: Mistral 出力が綺麗なページ単位ブロック境界を保つかは未検証のため、これは現状の主張ではなく**満たすべき要件**として記す。

**emit(curated.md に出すもの):**

- **セクションID + PDFページ範囲**(セクション見出し直下):

  ```md
  ## 第3章 注意機構
  Source: PDF p.12-18
  ```

- **軽量な機械向けページ境界マーカー**(ページが変わる箇所に挿入):

  ```md
  <!-- PDF p.14 -->
  ```

  引用精度を確保するため。HTML コメントで描画非表示=人間可読性のコストゼロ。ページ単位なので「段落単位・座標単位の参照は本文に入れない」原則には違反しない。

段落単位・座標単位の参照、ページ内座標、抽出ブロックID、OCR信頼度などは `--debug` 時の debug bundle に保存する(座標レベルの来歴は layout 解析が来る v2)。

*(改訂)* 原本「原文参照」L93-105 に block→page タグ要件とページ境界マーカーを追加(Q6)。

**metadata**

第一版の metadata は最小限にし、`curated.md` の frontmatter に格納する(別ファイルにしない=最小保存と両立)。

- `title`
- `source_pdf`
- `page_count`
- `course_name` / `lecture_name`
- `instructor`
- `date` または `term`
- `section_index`: セクションID、見出し、PDFページ範囲(block→page タグからの**派生ビュー**、手保守禁止)
- `glossary`: 著者の用語ゆれの**同義語マップ**(「これらは同概念」を AI 読者に伝える。後述「用語処理」)
- `processing_summary`: 使用した抽出・編集の概要。**OCR(Mistral)+ LLM 編集**、およびゲート統計(N 自動適用 / M 隔離 / K 拒否)
- `warnings`: 低信頼箇所、未解決の表・図・数式

本文中のページ参照(`Source:`)と `section_index` は、いずれも block→page タグからの派生ビューで**構築上一致**(手書き保守しない)。用途が異なる(本文即時文脈 vs 構造化索引)ため両方残す。

講義名や教授名は本文中に毎回残さず、metadata に一度だけ置く。
確信が低い項目は空欄ではなく `uncertain` として扱う。

*(改訂)* frontmatter 格納を明記、`processing_summary` を OCR 単源 + ゲート統計に更新、`glossary` 追加、ページ範囲の派生ビュー化(Q7-2, Q7-3)。

**ノイズ処理**

ノイズは削除前提ではなく、まず分類する。

- 文書全体の識別に必要: metadata へ移す
- 章やセクション境界として有用: heading として保持
- 各ページに繰り返されるだけ: header_footer として除外
- 内容理解に必要か曖昧: unknown として debug/warnings 対象
- 本文の意味を担う: paragraph / heading として保持

講義名や教授名は毎ページには残さないが、metadata には残す。
セクション名は反復ノイズではなく構造情報として使う。

**LLMの役割と編集モデル**

LLMは `curated.md` を全文清書しない。**編集権限はスクリプトが独占し、LLM は提案・分類・検査のみ**を行う。

LLM は **チャンク内エージェント**として動き、次のツールを持つ:

- `READ` / `GREP`(読み取り専用、無制限): 編集が必要な箇所の発見・位置特定・典型誤植の横断検索
- `EDIT`(スクリプト提供、唯一の単発変更経路): 定型処理できない局所変更
- `replace_all`(スクリプト提供、決定論ツール): GREP で見つけた系統的誤りを全該当に一括適用(LLM が判断、スクリプトが決定論的に実行)

**全ての変更は同一ゲートを通る:**(型検査・`before` の原文実在検証・diff ログ)。エージェントは生バイトをファイルに書かず、必ずツール経由。つまりエージェントの自律 ≠ 無制限の編集権限。

**変更のトリガーは3種:**

1. **自動 pre-pass**: 文脈フリーで普遍的に安全な規則(全ページの ≥N% に出る running header の除去、区切り線除去)のみ。最小限に留める。文脈依存ルール(ページ番号の文脈判定等)は blind に剥がさずエージェントの判断に委ねる。
2. **LLM 単発 `EDIT`**: 文脈依存・一回限りの変更。
3. **LLM 一括 `replace_all`**: 判断は要るが決まれば機械的・複数箇所の変更。

LLM が行うこと:

- ノイズ候補の分類
- OCR/抽出ミス候補の検出
- 見出し・箇条書き・段落構造の復元候補の提案
- 各提案の(任意の)理由メモ

実際の適用・ゲート・ログはスクリプト側が行う。`hashline` は `EDIT`/`replace_all` の適用バックエンドの一候補で、トークン削減が必要になった時に差し替える実装詳細。

*(改訂)* 原本「LLMの役割」L137-160 を「束縛されたチャンク内エージェント + スクリプトが権限独占 + 3トリガー」に書き換え(Q2)。自己申告 before/after パッチ列挙はやめ、diff はスクリプトが計算。

**ゲートと変更タイプ**

ゲートは二層。

**第1層 — 決定論ブライトライン不変条件(上書き禁止):**
LLM 特有の破滅的失敗モードのみを機械的に止める。ファジー判断でも上書きさせない。

- 新規の文・節の挿入(=捏造)→ **拒否**
- ノイズパターン非合致の大量本文削除 → **隔離(warnings)**

> **carve-out:** この「net-new テキスト拒否」は **LLM が著述する本文プローズ**にのみ適用する。block→page タグから決定論的に生成される**システム由来の構造/来歴注釈**(`Source:` 行、`<!-- PDF p.N -->` マーカー)は捏造ガードの対象外。これらは著述された内容ではない。

**第2層 — グレー境界(ファジー判断):**
固定数値が脆い境界。判定軸は **語集合の増減 × hunk 規模**。

- `ocr_char_fix` vs `paraphrase`: 小編集距離の同一語修正(`recieve→receive`)は忠実、別語への置換(`重要→大切`)は言い換え
- 構造復元(`linebreak_repair`/`list_restore`)vs 意味を変える再構成: 語集合保存でも規模が大きいと判断が要る

グレー境界の裁定者:

- **v1**: 人間(warnings に流す)
- **v2(完全自動化)**: **編集をしていない別コンテキストの新規レビュアーエージェント**を呼び、現物 diff(と最小限の原文)だけを渡して裁定。著者の自己承認はしない(writer / reviewer 分離)。

**変更タイプとゲート規則(素案、数値は実装/テスト時チューニング):**

| タイプ | 性質 | ゲート規則 | 既定 |
|---|---|---|---|
| `header_footer_remove` | 削除 | ≥N% のページに出る反復行パターンに合致 | 自動 |
| `page_number_remove` | 削除 | 番号パターン & ページ境界近傍 | 自動 |
| `linebreak_repair` | 修正 | 内容語保存、空白/改行のみ変化 | 自動 |
| `list_restore` | 修正 | マーカー付与のみ、本文語不変 | 自動 |
| `ocr_char_fix` | 修正 | 編集距離 ≤ 閾値 & 局所 | 自動 |
| `bulk_ocr_fix` (`replace_all`) | 一括修正 | 各該当が `ocr_char_fix` 条件 & スコープ限定 | 自動(ログ必須) |
| `paragraph_restructure` | 構造再編 | 語集合不変・規模大 | 隔離→warnings |
| `content_delete` | 削除 | パターン非合致の本文削除 | 隔離→warnings |
| `content_add` | 追加 | source に無い net-new 本文 | 拒否 |
| `summarize`/`paraphrase` | 意味改変 | 語集合変化 & 長さ保存 | 拒否(検出範囲)→残りは warnings backstop |

LLM の自己申告信頼度は**ゲートに使わない**(較正不能)。客観量(編集距離・語集合差分・hunk サイズ・パターン合致)で判定する。

*(改訂)* 原本「パッチ自動適用基準」L162-181 を型 enum + 二層ゲートに具体化(Q5)。信頼度ベース判定を客観量ベースに置換。継ぎ目A の carve-out を明記。

**用語処理**

著者の用語不統一は2種類に分け、**本文は著者の用語を統一するために書き換えない**(原文に忠実を貫く)。

| ケース | 例 | 扱い |
|---|---|---|
| OCR 由来の用語崩れ | 「アテンシ ョン」→「アテンション」、`attentlon`→`attention` | 同一語の崩れ修正=忠実。`bulk_ocr_fix` で自動 |
| 著者自身の用語ゆれ | 講師が「注意機構/アテンション/attention」を意図的に併用 | **本文は不変**。`glossary`(metadata)に同義語マップとして記録 |

**Pass1 用語表の役割 = 記述的な同義語マップ**(AI 読者への同義知識 + OCR 崩れ検出の参照)であって、**本文を正規化する契約ではない**。
見出し**レベル**の正規化(`#` vs `##`)は語を変えないので自動のまま。問題になるのは概念語の本文書換えのみで、それは行わない。

*(改訂)* 原本 L205「用語統一」を自動本文書換えから「同義語マップ記録 + OCR崩れ修正」に差し替え(継ぎ目B)。原文に忠実の背骨と整合。

**表・図・数式**

第一版の扱い。共通原則: **忠実にテキスト化できないものは `[X on PDF p.N]` で権威(PDF)へのポインタを残す**(無理に復元・合成しない)。

- **表**: 可能ならMarkdown tableへ変換。崩れる場合の挙動は OCR 出力品質依存のため実装時に詰める。安全側フォールバックは `[Table on PDF p.X]` ポインタ。
- **図・グラフ**: 画像そのものは `curated.md` に埋め込まない。図 = **verbatim キャプション(`figure_caption`)+ `[Figure on PDF p.X]` ポインタ**。図中テキストの無理な復元はしない(構造が壊れて誤誘導になる)。**要点の合成(旧「AI Note」)は v1 では行わない**(要約・教材化・捏造に該当し、非目標とゲート第1層に反する)。
- **数式**: 確信が低い場合は無理に復元せず `[Formula on PDF p.X]` のように原文参照を残す。
- 重要図の画像切り出しやリンクは将来拡張で、第一版の必須要件ではない。

*(改訂)* 原本「表・図・数式」L183-190 から「AI Note(要点合成)」を削除し、ポインタ原則を図・数式・破綻表に統一(Q3)。要点合成は来歴ラベル付き v2 opt-in。

**編集オーケストレーション**

作業方式は **単独責任者 + チャンク作業 + 全体再統合**。

1. **Global Planning Pass**
   全体を見て、章構造、用語(同義語マップ)、反復ノイズ、編集ルールを決める。LLM は read-only の分析者。この先決めがチャンク判断の一貫性(=チャンク化の副作用抑制)を担保する。

2. **Chunk Editing Pass**
   章・節・ページ範囲ごとに小さく処理する。各チャンクには全体方針、用語表、前後の短い文脈を渡す。LLM は提案者(視野=チャンク内)。

3. **Global Reconciliation Pass**
   1体のゲート付きエージェントが、**縮約ビュー(アウトライン / Pass1 用語表 / チャンク継ぎ目 / GREP)**上で、見出し整合性・チャンク境界の欠落・重複・ページ参照を検査する。安全な横断整合(OCR崩れの一括修正・見出しレベル正規化・ページ参照付与)はゲート経由で適用、残りは warnings。視野=チャンク横断。機構は Pass2 と同一(全文を文脈に載せず GREP/READ でたぐる)。

**「全体の読み流れ」検証は v1 から削除**(L74 非目標「人間が快適に通読する文書ではない」と矛盾し、成功基準にも無い。失う整合性は構造/用語/境界の各タスクが既にカバー)。

複数ワーカー並列は将来拡張。第一版では逐次チャンク処理でもよい。

*(改訂)* 原本「編集オーケストレーション」L192-207、再統合を縮約ビュー上のゲート付き単一エージェントに、読み流れを削除(Q4)。スケール矛盾を解消。

**自動で決めてよいこと / 人間確認が必要なこと**

自動で決めてよいこと:

- ヘッダー/フッター/ページ番号の除外(パターン合致)
- 明確なOCR誤りの修正(小編集距離)
- 見出し・段落・箇条書きの**構造**復元(語集合不変)
- PDFページ範囲の付与・ページ境界マーカー(システム生成、ゲート carve-out 対象)
- 大型PDFの章単位分割
- debug bundle の保存有無
- warnings への低信頼箇所記録

人間確認が必要なこと(v1 は warnings、v2 は別レビュアー):

- 本文の意味を変える削除
- 要約や圧縮
- 図表・数式の解釈
- 曖昧なノイズ除去
- PDF元本にない補足説明の追加
- 著者の用語ゆれの本文統一(=原則やらない)
- Web向け軽量エクスポート仕様
- 新しい入力形式の追加

**成功基準**

第一版の成功基準:

- 講義資料PDFから `curated.md` を生成できる
- 各セクションにPDFページ範囲がある
- 反復ヘッダー/フッター/ページ番号が本文から概ね除外される
- 主要な見出し・箇条書き・段落が保たれる
- 低信頼箇所は `warnings` に出る

**「破綻しない」の機械可読定義**(全て満たす):

1. クラッシュ/未処理例外なく完走
2. 出力が妥当(パース可能な Markdown + 妥当な frontmatter)
3. 致命的な内容欠落が無い(原文 content words の保持率 ≥ 床値。床値は実装/テスト時に固定)
4. 捏造ゼロ(passed `content_add` = 0。ゲート第1層で構築上保証)
5. 上記の他の成功基準を満たす

**第一版の非目標**

- Web上の claude.ai / chatgpt.com プロジェクト知識への最適化
- HTMLやリッチビューの生成
- 人間向けの美しいMarkdown清書 / 全体の読み流れの調整
- PDF内容の要約 / 図の要点合成
- 多源統合(text-layer 融合)/ 完全なOCR精度保証
- 図表・数式の完全復元
- Word / HTML / Google Docs 入力対応
- 複数ワーカーによる本格並列編集
- 人手レビューUI
- 情報の追加説明や教材化
- 著者の用語ゆれの本文統一

**横断的不変条件(設計の背骨)**

1. スクリプトが全編集権限を独占、LLM は提案/分類/検査のみ。
2. 全ての変更が同一ゲート(型・`before` 原文実在・diff ログ)を通る。可変なのはトリガーのみ(自動 pre-pass / 単発 EDIT / 一括 replace_all)。
3. block→page タグが唯一の source of truth、ページ参照は全て派生生成。
4. 「忠実にテキスト化できない → PDF ポインタ」共通フォールバック(図・数式・破綻表)。
5. writer と reviewer は別コンテキスト(自己承認禁止)。
6. 原文に忠実 > 整合性。著者の内容・用語は書き換えない。直すのは OCR 崩れと反復ノイズのみ。
